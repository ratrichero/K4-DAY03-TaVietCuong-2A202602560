🏥 1. Đề Tài Là Gì & Tại Sao Chọn Bệnh Viện Tim Hà Nội?

Giải quyết bài toán tư vấn y tế tim mạch với độ chính xác tuyệt đối, bài trừ ảo giác (Anti-Hallucination).

❤️ High-Stakes Medical AI

🎯 Đề tài là gì?

Hanoi Heart Hospital Assistant là Trợ lý Tác tử thông minh (ReAct Agent - AI Level 3) kết nối hệ sinh thái công cụ y tế qua giao thức mở Model Context Protocol (MCP). Hệ thống hỗ trợ bệnh nhân tra cứu hồ sơ bệnh án, theo dõi tình trạng bệnh lý tim mạch và đặt lịch thăm khám trực tiếp với bác sĩ chuyên khoa.

⚠️ Tại sao lại chọn đề tài Tim Mạch? (Tính cấp thiết)

  • Độ nhạy cảm sống còn: Bệnh tim mạch (tăng huyết áp độ 2, hở van tim...) đòi hỏi độ chính xác 100%. Sai lệch dữ liệu có thể dẫn đến nguy hiểm tính mạng.
  • Hiểm họa Ảo giác (Hallucination): Chatbot thông thường sinh văn bản theo xác suất, rất dễ bịa đặt số liệu bệnh án hoặc lịch khám không có thật.
  • Dữ liệu biến động thời gian thực: Hồ sơ bệnh án điện tử (EMR) và lịch trực bác sĩ là dữ liệu nội bộ bảo mật, không có sẵn trong trọng số huấn luyện của LLM.

🚀 Đột phá của giải pháp

Tác tử ReAct phân tách rõ ràng: LLM đóng vai trò bộ não suy luận và MCP Server đóng vai trò cánh tay hành động, chỉ trả lời dựa trên dữ liệu thật (Ground Truth) từ bệnh viện.

🎯 2. Tại Sao ReAct Pattern Lại Phù Hợp? (Agentic Fit Matrix)

Khung đánh giá 4 tiêu chí cốt lõi chứng minh tính tất yếu phải nâng cấp từ Chatbot lên ReAct Agent.

⭐ Tổng Điểm: 18 / 20 (Agentic Fit)
4 / 5
1. Multi-Step Reasoning
Xử lý chuỗi yêu cầu liên hoàn: Tra cứu bác sĩ điều trị ở bước 1 ➔ Sử dụng chính kết quả đó để đặt lịch tái khám ở bước 2.
5 / 5
2. Tool Interaction
Bắt buộc 100% phải gọi Tool để truy vấn Bệnh Án Điện Tử (EMR) và Lịch làm việc của bác sĩ. LLM tĩnh hoàn toàn không có dữ liệu này.
5 / 5
3. Dynamic Decision
Hành động rẽ nhánh linh hoạt theo Observation: Dữ liệu hợp lệ ➔ Trích xuất; `NOT_FOUND` ➔ Xử lý an toàn; Câu hỏi chung ➔ Trả lời trực tiếp.
4 / 5
4. Long Horizon Goal
Duy trì mục tiêu chăm sóc bệnh nhân xuyên suốt phiên làm việc, không bị trôi thông tin qua các lượt suy luận liên tiếp.

⚖️ So Sánh: Chatbot Cấp 2 vs ReAct Agent Cấp 3

• Chatbot Cấp 2 (Baseline): Chỉ phản hồi văn bản chung chung, không có công cụ, không thể truy cập hồ sơ BN2026001 và bất lực trước yêu cầu đặt lịch.

• ReAct Agent Cấp 3 (Dự án): Tự giác phát sinh hành động qua vòng lặp Thought ➔ Action ➔ Observation, lấy đúng dữ liệu y tế từ MCP Server và phản hồi chính xác 100%.

Kết luận kiểm định Agentic Fit:

Đạt 18/20 điểm (> 12/20) — Bài toán Bệnh viện Tim Hà Nội bắt buộc phải áp dụng mô hình ReAct Agent.

🔄 3. Workflow Vòng Lặp ReAct & Kiến Trúc MCP Chuẩn

Chuỗi suy luận từng bước (Thought ➔ Action ➔ Observation) kết hợp giao thức mở Model Context Protocol.

JSON-RPC 2.0 Protocol
01

🧠 Thought (LLM Suy luận ý định)

Tiếp nhận câu hỏi từ bệnh nhân, mô hình (Gemini 2.5 Flash) đối chiếu với các công cụ đã đăng ký để phân tích xem có cần dữ liệu y tế thời gian thực hay không.

02

🛠️ Action (Đề xuất gọi Tool qua MCP)

Nếu cần dữ liệu, LLM sinh cấu trúc Tool Call chuẩn JSON: patient_lookup(patient_id="BN2026002") và chuyển giao tới MCP Client (src/app.py).

03

👁️ Observation (MCP Server phản hồi kết quả)

MCP Server (src/mcp_server.py) nhận request qua chuẩn JSON-RPC 2.0, truy xuất database nội bộ và trả về kết quả quan sát (bác sĩ điều trị, tiền sử bệnh án) nạp lại vào ngữ cảnh.

04

🏁 Final Answer & Multi-step Execution

Nếu yêu cầu gồm nhiều bước (TC04), Agent tiếp tục gọi bước 2 (book_appointment). Khi đã gom đủ dữ liệu, Agent tổng hợp câu trả lời hoàn chỉnh tới bệnh nhân.

🌐 Kiến Trúc Phân Tầng Chuẩn MCP

Dự án hiện thực hóa kiến trúc Client-Server độc lập:

  • MCP Client (src/app.py): Tiếp nhận prompt, điều khiển vòng lặp ReAct, đếm latency_ms và xuất vết docs/trace_waterfall.json.
  • MCP Protocol: Giao tiếp bằng chuẩn gói tin JSON-RPC 2.0 có chứa jsonrpc, server, tool, result.
  • MCP Server (src/mcp_server.py): Đóng gói Tool Registry độc lập, bảo vệ dữ liệu bệnh viện khỏi rủi ro can thiệp trực tiếp từ LLM.

📊 Khả Năng Quan Sát (Observability)

Mọi hành động và quan sát đều được trích xuất minh bạch tại file docs/trace_waterfall.json với đầy đủ độ trễ (latency) từng bước thực thi.

🛠️ 4. Chi Tiết Công Cụ (Tools) & Cơ Chế An Toàn Y Tế

Đặc tả JSON Schema cho 2 công cụ cốt lõi và các tấm khiên phòng hộ Anti-Hallucination.

Zero Hallucination Guardrails
📁 Tool: patient_lookup Tra Cứu Hồ Sơ

Công dụng: Truy xuất bệnh án điện tử, tiền sử bệnh tim mạch và bác sĩ phụ trách. 

{
  "name": "patient_lookup",
  "parameters": {
    "type": "object",
    "properties": {
      "patient_id": {
        "type": "string",
        "description": "Mã bệnh nhân (vd: 'BN2026001')"
      }
    },
    "required": ["patient_id"]
  }
}
📅 Tool: book_appointment Đặt Lịch Khám

Công dụng: Khởi tạo lịch hẹn thăm khám với chuyên gia tim mạch chỉ định. 

{
  "name": "book_appointment",
  "parameters": {
    "type": "object",
    "properties": {
      "patient_id": { "type": "string" },
      "datetime_str": { "type": "string" },
      "doctor_name": { "type": "string" }
    },
    "required": [
      "patient_id", "datetime_str", "doctor_name"
    ]
  }
}

🛡️ Tấm Khiên Phòng Hộ Y Tế (Anti-Hallucination)

  • Không Bịa Bệnh Án: Khi tra cứu mã không tồn tại (BN9999999), Tool trả về NOT_FOUND. Agent được lập trình phản hồi lịch sự hướng dẫn gặp lễ tân, không tự chế thông tin bệnh.
  • Cơ Chế Xác Nhận Lịch Hẹn: Cấp mã đặt hẹn chuẩn xác (APPT-BN2026001-99) sau khi Tool Router thực thi thành công.
